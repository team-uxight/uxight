# 용어집 — 팀이 같은 말을 쓰기 위해

Jira 티켓 · Slack · 문서에서는 이 표의 말을 쓴다. 새 말이 필요하면 여기에 먼저 추가한다.

## 제품

| 용어 | 뜻 |
| --- | --- |
| **리서처** | 우리 서비스의 주 사용자. 실험을 만들고 결과를 보는 사람 (UX 담당자) |
| **운영자** | 서비스 관리자. 계정 · 한도 · 비용을 관리하고 실험을 강제 중단할 수 있다 |
| **프로젝트** | 실험 대상 사이트 하나. URL · 허용 도메인 · Task · Persona 를 묶는 단위 |
| **Task** | 가상 사용자에게 시키는 일 한 문장. 예: "장학금 신청 방법을 찾아라". **성공 기준**(어디에 도달하면 성공)이 같이 있다 |
| **Persona** | 가상 사용자 한 명의 설정 — 웹 숙련도 · 나이 · 배경 · 기기. 초보 / 숙련 / 모바일 3종이 기본 |
| **실험 (run)** | Task 하나를 Persona N명이 수행하는 한 번의 실행. 실험 하나 = 진단 하나 |
| **step** | 가상 사용자의 행동 한 번 (클릭 · 입력 · 스크롤 · 뒤로 · 완료). 실험은 step 의 나열이다 |
| **행동 로그** | step 마다 남는 기록 — 화면 · 생각 · 행동 · 결과. 진단의 입력 |
| **Friction** | 사용자가 막히거나 헤맨 지점. 4가지 유형: 길 찾기 혼란 · 조작 실패 · 과제 실패 · 과도한 단계 |
| **진단** | 실험의 행동 로그에서 Friction 을 찾아 정리한 것 |
| **개선안** | Friction 하나에 대한 고치는 방법 3가지. 리서처가 하나를 **승인**하면 재실험한다 |
| **패치** | 개선안을 실험용 화면에 적용하는 것. 4종: 라벨 바꾸기 · 요소 옮기기 · 요소 강조 · 도움말 넣기. 실제 사이트는 바뀌지 않는다 |
| **Before / After** | 패치 전 실험과 후 실험의 결과 비교 |
| **실험 대상** | 가상 사용자가 돌아다니는 사이트. 실서비스 계정에는 붙이지 않는다 — 로그인 없는 공개 페이지, 학교 홈페이지 사본(결함을 심은 것), 해지 흐름 mock 셋 |

## 시스템

| 용어 | 뜻 |
| --- | --- |
| **web** | 관리자 웹 (`apps/web`, React) |
| **api** | 서버 (`services/api`, Spring). 저장 · 조회 · 로그인 담당. 실행은 안 한다 |
| **agent** | 실행 서비스 (`services/agent`, Python). 가상 사용자를 실제로 돌린다 |
| **Watcher** | agent 안의 관리자. 실험을 시작하고, 한도를 넘으면 멈추고, 중단 요청을 받는다 |
| **Persona Agent** | 가상 사용자 한 명을 움직이는 LLM 루프 |
| **Driver** | 브라우저를 조작하는 부분 (Playwright). 화면을 읽고(**관측**) 행동을 실행한다 |
| **가드** | 행동을 실행하기 전에 검사하는 문. 허용 도메인 밖 · 결제/삭제 같은 위험한 클릭 · 정해진 행동 5종 밖은 막는다 |
| **관측 모드** | 화면을 모델에 보여주는 방식. **SoM** = 스크린샷에 번호 박스를 붙여 보여줌(기본) / **DOM** = 화면 요소 목록만 텍스트로 |
| **행동 5종** | 가상 사용자가 할 수 있는 전부: click · type · scroll · back · done |
| **한도** | 실험당 step 수 · 시간 · 토큰 · 동시 실행 수 · 하루 예산. 운영자가 정한다 |
| **kill switch** | 운영자가 모든 실험을 즉시 중단하는 버튼 |
| **감사 로그** | 누가 무엇을 했나 + 가드가 무엇을 막았나 기록 |
| **프록시** | 회사가 제공하는 LLM API 게이트웨이. 우리가 모델을 부르는 곳 |
| **walking skeleton** | 웹 → api → agent → DB → 웹까지 한 바퀴가 아주 얇게라도 도는 상태. 09/27 에 이게 되는지로 서버 언어를 확정한다 |
