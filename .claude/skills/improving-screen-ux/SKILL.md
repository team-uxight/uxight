# 화면 UX 개선 — 수치로 진단하고, 고른 뒤에 고친다

고칠 방법이 둘 이상 그럴듯하면 **사람이 두 안을 직접 보고 고른 뒤에** 코드를 고친다. 진단은 잰 값으로, 시안은 실제 디자인 토큰으로 만든다.

## 1. 띄워서 찍는다

- `cd apps/web && npm ci && npm run dev`. 로그인이 필요한 화면은 둘 중 하나로 띄운다.
  - dev 서버 API 에 붙인다(`apps/web/README.md` 의 프록시 설정) — 자기 계정으로 로그인.
  - 브라우저 도구(Playwright 등)의 `page.route` 로 `/api/auth/refresh` · `/api/users/me` 만 가짜 응답을 준다. 실제 계정 정보는 쓰지 않는다.
- 1280px · 390px 로 찍는다. 표 · 카드 구조는 코드에서 확인한다.

## 2. 진단 메시지 — 이 모양으로 보내고 답을 기다린다

```
문제 1. <현상> — <잰 값> — <왜 읽기 · 고르기 어려운가>
문제 2. …   (3개까지, 문제마다 한두 줄)
기본안: <3줄 이내>
질문: <답에 따라 안이 갈리는 맥락 질문 하나>
```

잰 값의 예: 안을 바꿔 눌러도 바뀌는 칸 0/11, 버튼 7개 중 주 행동 1개, 안 이름 글자 10px, 표마다 다른 같은 열의 x 위치(px). 아직 재지 않았으면 먼저 잰다.

## 3. A/B 시안 — 배치 · 위계 · 표 구조가 바뀔 때

정렬 · 간격 · 글자 크기만 고치면 시안 없이 4로 간다.

- HTML 한 파일로 만든다. `apps/web/src/styles/tokens.css` 의 변수를 복사해 쓴다.
- 질문마다 **공통 변경**(두 안에 똑같이) → **차이 하나** → 안마다 한 줄 → 같은 가짜 데이터로 그린 목업 둘.
- 안은 선택 카드로 나란히 둔다(A/B · 안 이름 · 한 줄). **추천 한 안과 이유 한 줄**을 적는다.
- 요청하지 않은 추가는 **'제안'**으로 표시하고 이유를 한 줄 단다.
- 맨 아래에 '데이터는 모두 가짜이고 눌러도 바뀌지 않는다'를 적는다. 대상 사이트 미리보기는 회색 상자와 '대상 사이트'라는 이름으로 그린다(실제 학교 · 회사의 로고 · 이름은 쓰지 않는다).
- 넘기기 전에 직접 열어 넘침 · 잘림을 고친다. Claude Artifact 도구가 있으면 비공개 링크로, 없으면 파일 경로로 넘긴다.
- 진단은 채팅에 두고, 시안에는 결정할 질문만 담는다.

## 4. 고른 뒤 고친다

- 고른 안대로 고친다. 새 라이브러리는 넣지 않는다(FE 리드가 정한다 — `apps/web/AGENTS.md`).
- 테스트 러너가 생기면 테스트를 먼저 쓴다. 지금은 `npm run lint && npm run typecheck && npm run build`.
- 같은 폭 · 같은 데이터로 다시 찍어 Before / After 를 나란히 보이고, 2의 잰 값을 다시 잰다.

## 5. 독립 리뷰 → dev 서버

- 다른 에이전트나 팀원에게 diff 와 고른 안만 준다(내 결론은 주지 않는다). 지적은 '사용자가 겪는 일'로 바꿔 전한다.
- PR 은 `feat/GACA-nn-…` → `fe`. 병합되면 dev 서버에 자동으로 배포되니 거기서 한 번 더 찍는다.

## 흔한 실수

| 실수 | 대신 |
| --- | --- |
| 추측으로 "이게 문제 같아요" | 재서 수치로 말한다 |
| 한 안을 정해 구현한 뒤 보여 준다 | 갈리면 A/B 로 먼저 고르게 한다 |
| 두 안이 여러 군데 다르다 | 공통은 똑같이, 차이는 하나 |
| 판단을 고르는 사람에게 떠넘긴다 | 추천 한 안과 이유 |
| 요청 밖 변경을 섞는다 | '제안'으로 따로 |
